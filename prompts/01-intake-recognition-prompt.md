# Промпт: распознавание документа (Intake)

Используется в воркфлоу `workflows/01-intake-recognition.json`, нода «Распознать документ (Vertex)».
Модель: **Gemini 2.5 Flash** (Vertex AI), `temperature: 0`, `responseMimeType: application/json`.
На вход вместе с текстом промпта передаётся изображение/скан документа (`inlineData`).

```
Ты бухгалтерский OCR. На фото документ. Сначала определи is_financial_document: true,
если это первичный финансовый документ с суммой к оплате (счёт-фактура, чек, акт,
накладная); false, если это другой документ без единой суммы к оплате (приказ,
распоряжение, договор, лицензия, справка, письмо и т.п.). Верни СТРОГО один
JSON-объект с полями: is_financial_document (true или false), recognized (true если
документ читается, false если качество скана не позволяет прочитать текст),
confidence (число от 0 до 1), doc_type, supplier, doc_number, doc_date, amount, vat,
reason. Если is_financial_document=false — amount, doc_number и vat можно оставить
null, это нормально: просто укажи doc_type и коротко опиши документ в reason. Если
is_financial_document=true, но номер, дата или сумма не читаются — поставь
recognized=false и опиши причину в reason. Ничего не придумывай. Ответь только JSON,
без пояснений.
```

## Зачем поле `is_financial_document`

Без него система пыталась силой распознать любой загруженный файл как счёт/чек/акт.
Внутренние документы вроде приказов об утверждении тарифов не имеют суммы к оплате —
цикл обработки зависал на требовании ручного ввода несуществующих данных. Теперь такие
документы автоматически помечаются `auto_excluded: true` и не блокируют расчёт сметы.
