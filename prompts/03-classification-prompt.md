# Промпт: классификация затраты по приказу №90 (RAG)

Используется в воркфлоу `workflows/03-classify-cost-rag.json`, нода «Классификация (Gemini)».
Модель: **Gemini 2.5 Flash** (Vertex AI), `temperature: 0`, `responseMimeType: application/json`.
Промпт собирается динамически: в него подставляются пункты приказа №90, найденные
поиском по смыслу в Pinecone (RAG) — модель классифицирует затрату строго по ним,
без собственных домыслов.

```
Ты классифицируешь статью затрат по Правилам формирования тарифов (приказ №90,
ред. 18.06.2026). Работай ТОЛЬКО с нормами ниже, ничего не выдумывай.

НОРМЫ (найдены по смыслу):
[1] <глава> п.<пункт>: <текст нормы>
[2] <глава> п.<пункт>: <текст нормы>
...

ЗАТРАТА:
наименование: <name>
сумма: <amount>
вид услуги: <service_type>

Верни СТРОГО один JSON-объект с полями: статья (строка), признак (одно из:
учитывается, не_учитывается, спорно), вид_услуги (строка), ссылка (глава и пункт
из норм выше), confidence (число 0..1), обоснование (кратко). Если среди норм НЕТ
прямого основания включить затрату в тариф — ставь признак не_учитывается или
спорно. Ссылайся только на нормы из списка. Ответь только JSON.
```

## Почему RAG, а не просто «спроси модель»

Тарифное регулирование требует, чтобы каждая учтённая затрата опиралась на конкретный
пункт приказа №90. Модель без доступа к тексту приказа может «придумать» обоснование.
Поэтому перед классификацией система ищет релевантные пункты приказа в векторной базе
(Pinecone, ~1262 фрагмента приказа) и передаёт их модели как единственный источник
истины — если прямого основания нет, затрата помечается «спорно» или «не_учитывается»,
а не включается в тариф произвольно.
